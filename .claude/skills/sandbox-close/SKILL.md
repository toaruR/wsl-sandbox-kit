---
name: sandbox-close
description: サンドボックス内プロジェクトの成果物を回収してから削除する(close_project_in_sandbox.py のラッパー)
disable-model-invocation: true
---

リポジトリルートで `python sandbox/close_project_in_sandbox.py --yes` を実行してください。
ユーザーが会話中で `--name NAME` / `--distro DISTRO` / `--force` を指定していれば、コマンドライン引数として渡す。

## 注意

- **破壊的操作のため、auto モード(自動承認)で動いている場合でも、実行前に必ずチャット上でユーザーへ
  「サンドボックス内のプロジェクト `<名前>` を削除してよいか」を明示的に確認すること。**
  権限モードに関わらずこの確認は省略してはならない。ユーザーの明示的な承諾を得られるまで
  スクリプトを実行しないこと。
- スクリプト自身もプロジェクト名の入力を求める確認プロンプトを持つが、Bash 実行では標準入力に
  応答できず `EOFError` で自動的に中断されてしまう。そのため、上記のチャット上の確認をもって
  ユーザーの承諾とし、`--yes` を付けてスクリプト側の対話確認をスキップして実行する
  (`--yes` を付けずに実行すると常に中断で失敗するだけなので、必ずセットで使う)。
- 削除前に `sync_from_sandbox.py` と同じ経路で git 履歴を `refs/remotes/sandbox/*` へ回収する。
  回収に失敗した場合、既定では削除を中止する(履歴の回収が不要と分かっている場合のみ `--force` で続行)。
- host 側の作業ツリーに未コミットの変更がある場合、スクリプトが警告を出力する。この変更は
  回収されず削除とともに失われるため、警告が出たら削除前にユーザーへ再確認すること。
- ディストロ自体(agent-sandbox)は破棄しない。対象はカレントディレクトリ名に対応する
  1プロジェクトのみ(ディストロ全体の破棄は destroy_sandbox.py だが、このスクリプトは
  移植先には配置されない)。
- 実行結果(標準出力・エラー)をそのままユーザーに報告する。
